## 1. Original Operational Audit Findings (`FINAL-OPERATIONAL-SIGNOFF.md`)

From the read-only sign-off audit on production `khadma-oran` (commit `3264bf5`), 6 items failed and 2 were blocked:
- **Item 1 (FAIL — Cloud Config):** Auth `callbackUri` pointed to `https://khadma-oran.firebaseapp.com/__/auth/action` (`defaultLocale: "en"`) instead of KHADMA's localized `/auth/action`; stale preprod preview domain remained in `authorizedDomains`.
- **Item 2 (FAIL — Cloud Config):** Cloud Functions App Check enforced (`HTTP 401` on missing/invalid tokens), but Firestore/Auth App Check service enforcement was `[]`.
- **Item 4 (BLOCKED — Cloud Billing):** `billingbudgets.googleapis.com` disabled (`403`); \$5 / \$15 / \$30 budget alerts unverified.
- **Item 5 (FAIL — Cloud Recovery):** Firestore `(default)` (`europe-west3`) had PITR disabled, Delete Protection disabled, and `0` backup schedules.
- **Item 7 (BLOCKED — Browser Audit):** 4 cases (`AUD-29`/`AUD-30` PWA install; `AUD-43`/`AUD-44` legacy phone email linking) remained unexecuted.
- **Item 8 (FAIL — Application):** Admin UI displayed only `g.flags` integer count; `reports` reasons and submission dates were never queried or shown.
- **Item 9 (FAIL — Application):** `post.rateLimit` hardcoded `"Maximum 5 annonces actives par numéro..."` (FR) and `"الحد الأقصى 5 إعلانات نشطة لكل رقم..."` (AR) instead of the authoritative backend quota (`3`, `5`, or admin-adjusted).
- **Item 10 (FAIL — Application):** `formatPay` and `.card-pay`/`.detail-pay` lacked BiDi isolation, reversing `min–max` visually in Arabic RTL.

## 2. Corrections Implemented (Code & Architecture)

- **Item 8 — Secure Admin Report Management:**
  - Added `AdminReportItem` (intentionally omitting `reporterId` to prevent reporter identity disclosure) and `ADMIN_REPORTS_PAGE_SIZE = 25`.
  - Added cursor-paginated `getAdminReportsPage(after, pageSize)` in `src/lib/db.ts` (bounded `limit(pageSize + 1)` query on `reports` ordered by `createdAt desc`, joining at most 25 unique associated `gigs` docs).
  - Added the **`Signalements` / `البلاغات`** tab to `src/pages/Admin.tsx` showing associated advertisement link, report reason, localized submission date, total report count, moderation status, and existing authorized moderation actions (`approveGig`, `restoreGig`, `hideGig`, `removeGig`) plus `"Charger plus de signalements"` pagination.
  - Public access to `reports` remains strictly denied in `firestore.rules` (`allow read: if isAdmin(); allow write: if false;`), and server-side duplicate/IP-Sybil prevention in `reportHandler.ts` is untouched.
- **Item 9 — Authoritative Dynamic Quota Error Messages:**
  - Extended `ListingHandlerError` in `functions/src/listingHandler.ts` and `HttpsError` forwarding in `functions/src/index.ts` to attach structured `details: { quotaMax, quotaUsed }` on `resource-exhausted` errors for both `create` and `republish`.
  - Added `extractQuotaMaxFromError(err, fallbackMax)` in `src/lib/format.ts` and replaced all hardcoded `5` / `"par numéro"` / `"لكل رقم"` strings in `src/lib/strings.ts` (`fr`, `ar`, `dar`) with dynamic `{max}` interpolation covering `3`, `5`, and admin-adjusted limits for active + pending ads.
  - Updated `src/pages/PostGig.tsx` and `src/pages/Employer.tsx` to render dynamic quota errors and verified editing existing ads succeeds when quota is full.
- **Item 10 — Arabic RTL Salary BiDi Isolation:**
  - Updated `formatPay` in `src/lib/format.ts` to isolate numeric values and `min–max` ranges with Unicode LRI (`\u2066`) and PDI (`\u2069`) markers.
  - Added `unicode-bidi: isolate` to `.card-pay`, `.detail-pay`, and `.pay-value` in `src/styles.css` (covering Browse cards, GigDetail, Saved, Employer dashboard, and Admin).
- **Item 2 — App Check Architectural Finding (Critical Compatibility Analysis):**
  - `src/firebase.ts` intentionally uses **lazy App Check initialization** (`ensureAppCheckInitialized()`) with `isTokenAutoRefreshEnabled: false` right before protected Cloud Function invocations so passive account-free public visitors never trigger billable reCAPTCHA Enterprise assessments (free tier: 10,000 assessments/month; \$1 per 1,000 thereafter).
  - **Warning:** Enabling Firestore App Check enforcement in Firebase Console *while lazy initialization is active* would immediately break public account-free browsing (`/jobs`, `/services`, `/listings`, `/gig/:id`). Because `firestore.rules` is already 100% server-authoritative (`allow write: if false;` on all collections; private `gigContacts` admin-only) and all mutating/PII callables enforce `enforceAppCheck: true` (verified `HTTP 401`), **recommendation is to keep Cloud Functions App Check enforced and NOT enable Firestore/Auth App Check enforcement at initial launch** (revisit only if abuse metrics warrant eager reCAPTCHA Enterprise spend, tested on staging first).

## 7. Required Production Configuration Changes (Owner Authorization Required)

1. **Item 1 — Firebase Auth Email Action URL & Authorized Domains (`khadma-oran`):**
   - *Platform restriction:* Firebase Auth shares one custom Action URL (`callbackUri`) across `verifyEmail`, `resetPassword`, and `recoverEmail`, and blocks arbitrary HTML body editing without custom SMTP. Per-request language is already localized via `auth.languageCode = lang` (`fr` / `ar`).
   - *Action:* Firebase Console -> Authentication -> Templates -> Edit -> Customize action URL -> set to `https://khadma-oran.web.app/auth/action`; set default template language to **French (`fr`)**; remove stale `khadma-oran--preprod-5p4skzmk.web.app` from Authorized Domains.
2. **Item 4 — Cloud Billing Budget Alerts (\$5 / \$15 / \$30):**
   - *Console steps (no API activation required):* Google Cloud Console -> Billing -> Budgets & alerts -> **Create Budget** -> Scope: Project `khadma-oran` -> Budget type: Specified amount **\$30** -> Set alert thresholds at **17% (\$5)**, **50% (\$15)**, and **100% (\$30)** (actual + forecasted) -> Enable email notifications to billing admins.
   - *Important distinction:* GCP Billing Budgets trigger **email/Pub-Sub notifications only** — they are **NOT hard spending caps** and do not automatically disable services.
3. **Item 5 — Firestore Production Recovery (`khadma-oran`, `europe-west3`):**
   - **Recommended minimum reliable launch configuration:**
     1. Enable **Delete Protection** (`DELETE_PROTECTION_ENABLED`) — **\$0.00/mo**.
     2. Enable **Point-in-Time Recovery (PITR)** (7-day microsecond recovery window) — ~\$0.15–\$0.16/GiB-month.
     3. Enable **Weekly Scheduled Backup** (4-week retention) — ~\$0.03–\$0.04/GiB-month per retained snapshot.
   - *Restore procedure:* Restore into a new database or target collection via `gcloud firestore databases restore` (\$0.20/GiB restored), validate data integrity, and never relax `firestore.rules`.

## 2. Production Cutover Runbook (Phase 6C — 17-Step Zero-Bypass Procedure)

> **CRITICAL:** Firestore Security Rules alone do NOT block Firebase Admin SDK writes from existing deployed Cloud Functions or CLI scripts. Steps 5–7 freeze BOTH direct-client writes AND privileged server mutation paths before migration runs.

1. **Confirm explicit owner authorization** for Phase 6C production cutover on `khadma-oran` and verify Phase 6B staging pilot sign-off.
2. **Verify current production release & rollback baseline:** Record live Hosting version (`3ee08b82d74bdf36`), live V1.3 commit (`ec8347052c726100c0185dcb94fe872f41d8756c`), and run `node scripts/verify-deploy-target.mjs --target=production --project=khadma-oran`.
3. **Verify production backups & recovery capability:** Trigger an on-demand Firestore export (`gcloud firestore export gs://<backup-bucket>/pre-v14-<YYYYMMDD>`) and confirm PITR/backup status in `europe-west3`.
4. **Deploy composite indexes first (`firestore.indexes.json`)** via `firebase deploy --only firestore:indexes -P production` and wait until 100% report `READY` (`status+expiresAt`, `posterUid+status`, `status+createdAt`, `flags+createdAt`).
5. **Activate controlled maintenance window:** Announce brief maintenance window (5–15 min); pause any existing admin/CLI scripts and confirm no operator is mutating production Firestore.
6. **Block legacy direct-client mutations FIRST:** Promote `firestore.rules.v14-cutover` to `firestore.rules` and deploy `firebase deploy --only firestore:rules -P production`. Public read-only browsing stays available; all direct client writes to `gigs`, `gigContacts`, `employers`, `settings`, `auditLogs`, and `listingIdempotency` are immediately blocked.
7. **Freeze/control existing privileged server mutation paths:** Confirm no V1.4 mutation callables are deployed yet (V1.3 only has `getGigContactLink` and `reportGigListing`, which do not create/edit/quota-reconcile employer listings); confirm no admin console/script writes are active during Steps 8–12.
8. **Run migration dry-run:** Execute `migrate-legacy-employers.mjs --cutoff=<EXPLICIT_ISO_TIMESTAMP>` (dry-run default, 0 writes) against `khadma-oran`.
9. **Validate legacy employer eligibility & proposed quota counts:** Review dry-run output (`eligibleLegacy`, `skippedPostCutoff`, `created`, `reconciled`) to confirm zero post-cutoff phone accounts are grandfathered and every legacy UID's reconciled `activeCount` matches ground truth.
10. **Execute authorized migration:** Run `migrate-legacy-employers.mjs --cutoff=<EXPLICIT_ISO_TIMESTAMP> --apply` (idempotent; preserves all existing UIDs, phone providers, and listing ownership).
11. **Explicitly initialize `settings/marketplace`:** Run `initMarketplaceSettings --apply` setting `requirePreApproval: false` and `remoderateMaterialEdits: true` (never overwriting if already configured).
12. **Validate migration results & ownership preservation:** Spot-check `employers/{uid}`, `settings/marketplace`, and existing `gigs` ownership (`posterUid` unchanged).
13. **Deploy compatible Cloud Functions (`europe-west1`):** `firebase deploy --only functions -P production` (`manageEmployerListing`, `adminManageMarketplace`, `expireStaleGigs`, `getGigContactLink`, `reportGigListing` with `enforceAppCheck: true`).
14. **Verify hardened rules & backend authorization:** Confirm unauthenticated/non-App-Check calls are rejected (`401`/`failed-precondition`), direct client writes are denied, and `settings/marketplace` is readable only by admin.
15. **Deploy certified V1.4 Hosting bundle:** Build with `.env.production.local` (`VITE_FIREBASE_ENV=production`, `VITE_FIREBASE_PROJECT_ID=khadma-oran`, NO `VITE_USE_EMULATORS`) and run `firebase deploy --only hosting -P production`. (`index.html` and `sw.js` use `Cache-Control: no-cache` so cached V1.3 PWAs upgrade cleanly.)
16. **Execute production smoke verification:** Test unauthenticated browse/search/contact, verified-email employer post/edit/archive, admin moderation toggle ON/OFF, live App Check attestation, and SMS region allowlist (`+213` only).
17. **Close maintenance window** only after all smoke gates pass; enable Firestore TTL policies (`contactRateLimits.expireAt`, `reportRateLimits.expireAt`, `listingIdempotency.expireAt`) and billing alerts (\$5 / \$15 / \$30).

## 3. Secure Rollback Runbook (All 9 Failure Scenarios)

> **Golden Rule:** NEVER automatically restore insecure V1.3 direct-client write rules. Preserve all V1.4 data (`employers`, `settings`, `auditLogs`, `gigs`) and employer ownership. When full rollback cannot preserve V1.4 security invariants, keep hardened rules active as a **secure read-only maintenance fallback**.

| Failure Scenario | Immediate Safe Action | Recovery Path |
|---|---|---|
| **1. Failed index creation** | Abort before Step 6; production remains untouched on V1.3. | Fix index definition, redeploy indexes, verify `READY`. |
| **2. Partial migration** | Keep hardened rules active (read-only browse, writes frozen). | Re-run idempotent `migrate-legacy-employers.mjs --apply` or restore from Step 3 pre-cutover Firestore export. |
| **3. Failed Functions deployment** | Keep hardened rules active; do NOT deploy V1.4 Hosting. | Fix and redeploy Functions; browsing remains online in read-only mode. |
| **4. Failed Hosting deployment** | Roll back Hosting to V1.3 (`firebase hosting:clone` / version `3ee08b82d74bdf36`) while keeping hardened rules (browse works, posting paused) until V1.4 Hosting is fixed. | Fix Hosting bundle and redeploy V1.4 Hosting. |
| **5. Authentication failure** | Verify Email/Password provider & authorized domains (`khadma-oran.web.app`). | Fix Auth console config; existing UIDs/data are untouched. |
| **6. App Check failure** | Verify `VITE_RECAPTCHA_SITE_KEY` matches `khadma-oran` reCAPTCHA Enterprise key & allowed domains; do NOT disable `enforceAppCheck: true` in code. | Correct site key/domain allowlist and redeploy Hosting. |
| **7. Incorrect quota reconciliation** | Pause new creates via Admin moderation ON or maintenance freeze. | Re-run idempotent reconciliation script; adjust individual employer quotas via `adminManageMarketplace`. |
| **8. Scheduler failure (`expireStaleGigs`)** | Pause Cloud Scheduler job; `getGigContactLink` and UI defensive filtering still block expired ads from contact/display. | Inspect Cloud Logging, fix, and run bounded manual `Run now` triggers. |
| **9. Cached V1.3 PWA incompatibility** | Hardened rules reject stale V1.3 direct-client post attempts cleanly; `no-cache` on `sw.js` & `index.html` forces update on reload. | No insecure rules rollback; users refresh to receive V1.4 PWA. |
